# Meta Quest 3 (Horizon OS, Snapdragon XR2 Gen 2) - recorded live off the
# headset over adb, running tools/record_fixture.sh unmodified on the device.
#
# Four properties here exist in no other fixture:
#
# 1. TWO "sockets" on a phone-class SoC. physical_package_id really is 0 for
#    cpu0-1 and 1 for cpu2-5: this kernel publishes CLUSTERS as packages. The
#    detector reports that faithfully instead of second-guessing the kernel, and
#    core_id RESTARTS inside each package (0,1 then 0,1,2,3) - so the
#    per-package core_id disambiguation is the only thing keeping cores 0-5
#    distinct. Get that wrong and six cores collapse into four.
# 2. NO cache metadata AT ALL. Every index dir exists and publishes level, type
#    and shared_cpu_list, but there is no `size` and no `coherency_line_size`
#    anywhere in the tree - so every size_bytes AND every line_bytes is 0,
#    L3 included. "The kernel didn't say" taken to its limit.
# 3. IDENTICAL MIDR across two capacity tiers. All six cores report CPU part
#    0xd4b (3403) while cpu_capacity splits 848 / 1024 - the same silicon binned
#    and clocked differently. cix-p1's part split MATCHED its capacity split;
#    here the part carries no signal and capacity is the sole kind input. Both
#    tiers sit at or above 3/4 of max (848/1024 = 0.83), so everything is
#    Performance and BOTH Efficiency and LpEfficiency come out empty.
# 4. NO /sys/devices/system/node directory whatsoever, so the degenerate
#    single-node NUMA fallback is what produces numa_node_count=1.
#
# Only 6 of the SoC's 8 cores exist: online, present and possible all read 0-5,
# because the headset reserves the remainder below anything userspace can see.
# Identity (vendor/model/features) is never asserted in fixtures - worth noting
# that ARM /proc/cpuinfo carries no model-name field at all, so this machine has
# no model string to assert even if fixtures did.
